## 一、先说个反直觉的事

大部分人对"AI 摄像头"的理解是:摄像头拍画面 → 传到云端 → 云端 AI 跑模型 → 返回结果。

这套在很多场景**根本不成立**:

- 车上的行车记录仪,跑在高速上,哪来稳定的网?
- 工厂产线、园区周界,数据**不让出厂、不让上云**;
- 机器人、智能眼镜,要的是**毫秒级实时**,等一趟云端往返,黄花菜都凉了。

所以真正的需求是:**AI 直接跑在设备本地算力上,拔了网线也能认人、也能看懂画面。**

这件事,我做了。下面不讲虚的,讲点实在的——它难在哪,我怎么落地的,以及这门生意到底值不值得碰。

## 二、它到底难在哪

会调云端 API 的人很多,能把 AI **塞进低算力量产设备、还跑得稳**的人很少。难点有三:

**1)算力极限下的工程。** 记录仪、眼镜这类设备,芯片算力和功耗都卡得死。要让 YOLO 检测、甚至视觉大模型在上面实时跑,靠的不是会写 Python,而是从底层固件、音视频编解码、到推理调度整条链路的压榨。

**2)"看懂"比"识别"高一个维度。** 传统检测只会"数物体"——画面里有几个人、几辆车。我做的设备端**视觉大模型**,能描述整个场景、**读出画面里的招牌/车牌/铭牌文字**,还能自然语言问答。同一帧画面,断网走设备本地模型,联网可挂云端大模型,客户按成本和合规自己选。

**3)量产的确定性。** Demo 跑通和量产跑通是两回事。掉电会不会丢录像?连续跑一年会不会崩?多平台 SoC 换芯片要不要重写?——这些"不出事"的能力,才是工厂真正买单的东西。我这套:看门狗自愈、断电保护、一套固件覆盖多平台芯片,累计十几万录像文件无损。

## 三、我已经把它做进了 4 个领域的量产设备

不是构想,是真机已落地、在量产线上的(客户已脱敏):

- **行车记录仪 / 车队**:低算力端侧 AI + 音视频编解码,掉电不丢录像、预录、缩时全解决,远程实时(WebRTC)+ 云端录像。量产出货约 **5 万台/月**。
- **安防摄像头 / 园区**:整套系统架构 + 端侧检测,**看懂场景、读出招牌车牌、断网不泄露**。约 **10 万台/月**。
- **人形机器人 / 巡检**:机器人视觉架构 + 边缘 AI,音视频对接约 300ms,直连 ROS 感知与决策。约 **500 台/月**。
- **智能眼镜 / 第一视角**:极致功耗体积下的系统架构 + **AI 视觉对话**(看着画面直接问、读出文字)。约 **5000 台/月**。

四种完全不同的设备,用的是**同一套端侧 AI 视觉栈**。这本身就说明问题:换谁的硬件,只是把这套成熟能力搬过去,**单个项目大约 2 个月就能跑通**。

## 四、和"云端 API / 通用外包"的区别

| | 常见做法 | 这套方案 |
|---|---|---|
| AI 在哪跑 | 云端,断网即瘫、有时延、数据出门 | **设备本地推理**,拔网照跑、不泄露 |
| 能力 | 只会数物体 | **看懂场景 + 读出画面文字** |
| 换芯片 | 要重写 | **一套固件多平台** |
| 交付 | 挂别人 logo | **设备/App/门户/云 整套白标成你的品牌** |

## 五、说点诚实的(不吹)

- 设备端视觉大模型现在确实有**差异化窗口**,但不是永久护城河——所以我打法是"先落地、绑量产、做进客户产品线",而不是赌一个永远领先的算法。
- 它**不适合**所有场景:对延迟和隐私不敏感、纯云端就够用的需求,没必要上端侧。
- 它的价值在**特定硬骨头**:低算力跑不动、断网要可用、数据不能出门、要读画面里的字、要融进机器人/车/眼镜。
